Your Mac.
Your choice.

Machogs checks your Mac locally. Optional analytics help us understand whether people find the app and keep using it. You can say no and use every feature.

Website analytics

Website analytics are off until you allow them.

What the website shares

Only after you allow analytics: a landing-page visit, a click on a Mac download button, the button’s position, the advertised app version, and an event time and random identifier. A new identifier is made for each page load. We do not join it to your app activity.

There are no analytics cookies, persistent visitor identifiers, session recordings, or automatic capture of what you type. Your choice is stored in this browser’s local storage. We honor Global Privacy Control and Do Not Track. Query strings, referral URLs, and browsing history are not sent in our events.

What the updated app shares

The next app build replaces basic usage tracking with “Share feature usage”, off by default, in Settings → Privacy. It requires a fresh choice even if you allowed the older analytics. If enabled, it sends app opens, onboarding completion, feature scan counts and manual action outcomes, app version and a random installation ID. Scan events can include background checks; they do not measure active people.

No process names, paths, command arguments, scan contents, messages or cleanup receipts are sent. Turning sharing off cancels pending sends and resets the local identifier. It does not erase events already received. Existing released apps retain their earlier first-use and weekly-use measurement until you install an updated build.

CLI sharing

The CLI sends nothing unless you explicitly set MACHOGS_ANALYTICS=1. It then sends the command category and success/failure with a random installation ID. Unset that variable to stop sharing. The app's bundled engine does not send separate CLI events.

Where the data goes

The updated app and CLI use self-hosted Native Analytics. The receiver stores the connection IP and keeps events for 90 days. No producer secret is embedded. Sending is best-effort; offline events are not replayed. The website keeps its separate PostHog choice and per-page IDs. Previously released apps also use PostHog. App and website IDs are not joined.

The site and downloads are hosted by GitHub. The landing page also requests fonts from Google Fonts. Those services handle ordinary web requests under their own privacy policies, independently of the optional analytics choice.

What the numbers mean

These are counts of people who choose to share, not a count of every install. Downloads can include repeats and testing. An existing user opting in is separate from a new setup. Clearing preferences or opting out and back in can create a new installation identifier. Website and app identities are kept separate, so we cannot attribute an app install to a particular visitor or ad.
